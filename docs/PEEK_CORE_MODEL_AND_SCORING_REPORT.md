# Peek 模型调用与评分核心报告

> 审计版本：2026-07-30  
> 范围：内容分析、技能抽取、匹配度、含金量、笔记、随时问答、双语转换、画像更新与时间节省计算。

## 1. 产品责任

Peek 的用户只需要提交内容链接或直接提出自然语言问题。用户不负责写提示词，也不需要理解模型、JSON、Agent、SSE 或评分公式。

系统负责：

1. 把视频、文章或论文转换为可核验的来源文本。
2. 将来源、学习画像和严格任务规范封装为完整分析请求。
3. 校验模型输出，只接受符合目标结构的结果。
4. 在服务端重新计算匹配度，避免模型自行决定最终个性化分数。
5. 把 Markdown 笔记渲染为阅读版，并按需生成和缓存英文版本。
6. 问答时自动回到原文与分析报告寻找证据，不要求用户写“请逐步分析”等提示。

## 2. InfiniSynapse 调用链

所有密钥只存在于服务端。任务调用遵循：

1. 生成一次性 `connId`。
2. 先建立 InfiniSynapse SSE 事件连接。
3. 再发送 `newTask`。
4. 从创建响应或 SSE 事件中取得 `taskId`。
5. 接收实时事件；任务完成后同时查询消息与工作区结果。
6. 只接受通过结构校验的 JSON；主分析异常时允许一次定向修复。
7. 刷新页面后通过保存的 `taskId` 恢复，不依赖浏览器持续在线。

通用 JSON 任务解析不再“看到任意对象就返回”。每类调用必须声明验收条件：

- 问答：必须存在非空 `answer`。
- 报告翻译：必须保持 `schemaVersion=xianjian.v1` 且包含片段数组。
- 笔记翻译：必须返回与原笔记数量和 ID 完全一致的 `items`。

## 3. 主内容分析请求

### 输入

- 内容类型：视频、文章或论文。
- 公开链接，或用户提供的字幕/正文。
- 内容标题和估算时长。
- 自动学习画像：方向、水平、项目、已知主题、偏好。
- 已入架技能点：技能键、领域、掌握度与可信度。

### 模型必须完成

1. 独立评价内容本身的含金量。
2. 判断内容与当前用户的主题相关度。
3. 视频给出 3–7 个有效时间码；文章/论文给出 3–7 个可回到原文的章节定位。
4. 每个片段标记 `watch` 或 `skip`，并给出具体价值和证据。
5. 区分新增知识与已知/重复知识。
6. 抽取专业技能点，层级固定为：

   `类别 → 专业领域 → 规范知识点`

7. 技能名称必须是 2–20 字规范名词短语，例如：

   - 挂谷猜想
   - 豪斯多夫维数
   - 粘性挂谷集
   - 多尺度归纳

8. 人物、奖项、论文事件、完整结论和摘要长句只能作为证据，不能成为技能节点。
9. 无法读取来源时必须报错，禁止根据标题编造内容。

### 输出校验

- JSON 结构固定为 `xianjian.v1`。
- 视频至少 3 个 `startSeconds < endSeconds` 的片段。
- 文章/论文至少 3 个带标题或原文短句定位的阅读片段。
- 所有分数限制在 0–100。
- 推荐时长由服务端合并片段区间计算，模型不能直接决定。
- 技能名称再次经过规范化和分类过滤。

## 4. 随时问答请求

问答不是把用户的一句话直接转发给模型。Peek 自动提供：

- 当前内容正式标题。
- 完整分析报告。
- 最多 60,000 字的来源字幕或正文。
- 用户当前使用的回答语言。

模型内部任务流程：

1. 判断问题属于定义、列举、因果、证明步骤、例子、对比或应用。
2. 优先从原文检索直接证据，再用报告补充上下文和定位。
3. 对“几个要素分别是什么”一类问题，必须列全每一项，并分别解释：

   - 是什么；
   - 为什么重要；
   - 在内容中如何出现。

4. 自动理解口语、简称和轻微错别字。
5. 开头先给直接结论，再展开说明。
6. 能确认时给出时间码、章节或原文依据；不能确认时禁止伪造。
7. 同时生成一份独立可读、可一键加入笔记的批注。

严格输出：

```json
{
  "answer": "完整回答，可含简洁 Markdown",
  "note": "可独立阅读的学习笔记",
  "evidence": ["1–5 条直接依据"],
  "confidence": "high | medium | low"
}
```

## 5. 笔记系统

### 中文核心笔记

核心笔记不再只是摘要，固定整理为：

1. 核心结论。
2. 这篇内容解决什么问题。
3. 关键知识点及具体解释。
4. 核心思路、时间码/章节和证据。
5. 新获得的知识。
6. 对当前用户的价值。
7. 可以继续追问的问题。

Markdown 只作为存储格式，页面使用安全组件渲染标题、列表、段落和加粗文本，不直接显示 `#`、`##`、`-` 或 `**`。

### 英文笔记

- 用户主动点击 English 后才调用模型，不自动消耗额度。
- 必须保留每条笔记 ID、标题层级、列表结构、数字、时间码和证据。
- 专业术语采用通行英文，必要时首次出现保留中文括注。
- 翻译结果按“内容 + 语言 + 当前笔记内容哈希”缓存。
- 中文笔记发生新增、修改、删除或重建时，旧英文缓存立即失效。

### 笔记内随时问答

每本笔记右侧提供带 Peek 吉祥物的问答区。它与分析页问答使用同一个“原文 + 报告”检索式提示词；回答可一键加入当前笔记。

## 6. 内容含金量

内容含金量与用户画像无关。

当前优先使用主分析返回的 `signals.value`。若缺失，则使用确定性回退公式：

```text
内容含金量 =
  专业深度 × 0.35
  + 来源可信度 × 0.35
  + (100 - 推广占比) × 0.15
  + (100 - 重复度) × 0.15
```

结果四舍五入并限制在 0–100。

审计说明：当前 `signals.value` 的主分仍由模型依据“信息密度、专业深度、原创洞察、可验证性、完整度”综合给出；四项确定性公式是缺失时的回退。若比赛要求所有含金量必须完全公式化，应将主路径也改成四维计算。

## 7. 技能关联分

对目标内容的每个技能点，与书架画像比较：

```text
完全相同技能键：96
满足其前置技能：84
同一专业领域：72
无直接关系：18
画像为空：50（中性）
```

模型给出的主题相关度只占 35%，画像中的结构关系占 65%：

```text
单技能关联分 =
  模型主题相关度 × 0.35
  + 画像结构关系分 × 0.65
```

每个技能的加权权重：

```text
权重 = 内容覆盖度 × max(0.25, 抽取可信度 / 100)
```

最终“技能关联”是所有技能关联分的加权平均。

## 8. 知识增益

```text
单技能知识增益 =
  (100 - 分析前掌握度)
  × 内容覆盖度 / 100
```

最终“知识增益”是所有技能知识增益的加权平均。

含义：用户已经掌握的技能不会因为视频反复提到而获得高增益；覆盖很浅的内容也不会获得高增益。

## 9. 难度适配

先计算内容深度和用户下一阶段水平之间的距离：

```text
目标学习水平 = min(100, 当前掌握度 + 25)

水平适配 =
  100 - abs(内容深度 - 目标学习水平)

单技能难度适配 =
  水平适配 × 0.60
  + 前置知识适配 × 0.40
```

最终“难度适配”是所有技能难度适配的加权平均。

## 10. 最终匹配度

先计算技能适合度：

```text
技能适合度 =
  技能关联 × 0.50
  + 知识增益 × 0.30
  + 难度适配 × 0.20
```

内容含金量系数：

```text
含金量系数 = 0.15 + 0.85 × 内容含金量 / 100
```

最终匹配度：

```text
最终匹配度 = 技能适合度 × 含金量系数
```

该乘法保证“主题很相关但内容很差”的视频不能获得高匹配度。

计算目标内容时会从画像数据中排除目标内容自己，避免自我匹配。这个实现细节只在帮助提示和本审计报告中出现，不占据用户主界面。

## 11. 最终判决

```text
内容含金量 < 35 或 匹配度 < 25
→ 跳过

内容含金量 ≥ 65 且 匹配度 ≥ 70
→ 值得看

其他情况
→ 选择性看
```

## 12. 技能掌握度更新

加入书架不等于掌握。技能增量：

```text
掌握增量 =
  (100 - 原掌握度)
  × 内容覆盖度 / 100
  × 内容深度 / 100
  × 参与系数
```

参与系数：

```text
稍后看：0.10
纳入书架：0.25
标记看完：0.55
```

因此仅收藏只会产生很小的“已接触”增量；真正看完才产生更明显变化。

## 13. 推荐时长与节省时间

服务端把所有 `watch` 片段按时间排序并合并重叠区间：

```text
推荐时长 = 合并后 watch 区间总长度
节省时间 = max(0, 原内容总时长 - 推荐时长)
```

文章和论文使用章节数量与定位，不伪造视频式节省时长。

## 14. 双语报告

- 切换网站界面不会自动翻译报告。
- 用户点击 English 后才请求完整报告翻译。
- 字段名、版本、数字、ID、时间码、判决和技能键不变，只翻译用户可见文字。
- 翻译结果按“分析 ID + 语言”持久缓存。

## 15. 限额与失败处理

- 每个学习空间每天最多 3 次主分析。
- 双语转换和随时问答采用独立短任务。
- 问答、报告翻译和笔记翻译各自有结构验收条件。
- 来源不足时明确说明，不使用标题猜测。
- JSON 不合法时主分析只修复一次，避免无限消耗。
- 超时任务保留恢复信息，用户刷新或离开页面不会丢失。

## 17. 建议验收问题

1. “视频提到的三个要素分别是什么？逐项解释。”
2. “挂谷猜想、豪斯多夫维数和 Assouad 维数是什么关系？”
3. “这个证明最关键的三步分别解决了什么障碍？”
4. “哪些结论来自原文，哪些只是报告的概括？”
5. 将同一笔记切换到 English，检查专业术语、时间码和列表是否完整保留。
6. 修改一条中文笔记后再次切换 English，确认翻译缓存已更新。
